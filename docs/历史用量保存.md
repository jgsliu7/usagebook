# 历史用量保存

`serve` 默认使用独立的 `usage-ledger.db`。首次发现来源时扫描当前可读历史，保存固定导入目标，随后分批保存、独立发布。发现新工具、新根或新的适配能力时会创建相应补扫范围，不使用一个全局“导入过了”的开关。

看板的页面读取、筛选和图表查询直接使用本地库，不等待采集完成。后台完成一个来源的补扫后，该来源即可更新，不必等其他来源。正常文件追加从持久检查点继续；数据库新行使用物理游标发现，因此旧日期的新记录、跨日会话不受“只扫今天”限制。历史完整性校验默认每 24 小时在后台执行，`ledger audit` 或 `ledger refresh --full` 可立即要求校验。

文件身份、大小、修改时间和有界内容锚点共同校验检查点。任意旧位置改写、数据库旧行修订或 rowid 复用可能需要等低频校验才发现；它们保存为新证据，不改写已经采用的贡献。整体 JSON 文档与压缩归档在变化时仍可能需要完整解码；资源预算不足会明确留下未完成或缺口，不假装已读完。

兼容解析仍使用独立的持久扫描缓存；清除这个可重建缓存最多增加后台解析工作，不清除主账本或阻塞已保存看板。SQLite 来源另在主账本保存必要的白名单字段，模型归属索引不保存对话正文。兼容的会话累计值仍遵守原来源语义；只有已采用的账本贡献承诺数值冻结，不能把累计快照的多个版本相加。

## 保存与采用状态

| 状态 | 含义 |
| --- | --- |
| 已保存证据 | 白名单用量字段已提交到 usagebook；源文件删除不会删除它们 |
| 来源报告用量 | 明确采用固定历史快照，已进入看板；逐请求最终性尚未核实，质量为 `source_reported` |
| 已确认用量 | 请求身份、口径与结束条件满足该适配器规则，已进入正式账本 |
| 有缺口或待核对 | 未读完、源损坏/消失、身份不明、累计/镜像重叠或最终值未确认 |

保存待核对证据不等于已把其中数字加进看板。未准入来源继续走 live 查询，其当前合计仍可能随外部记录变化。`history_protection`、`evidence_supported`、`durable_supported` 和 `initial_import` 提供机器可读状态；不把“初始目标已处理”说成“所有历史永远完整”。

## 准入边界

下表说明默认的原生记录准入；满足后文完整性条件时，除 CC 外的已支持证据来源也可以明确选择旧查询的来源报告基线。采用基线会改变该来源的查询路由，但不会把这些记录升级为已核实请求。

| 来源 | 可正式确认的范围 | 仍保存待核对的范围 |
| --- | --- | --- |
| Claude Code | 有原生请求身份及明确结束原因的 assistant 用量 | 流式中间观察、身份或时间不明 |
| Codex | 有原生 response ID 的逐次用量记录 | 旧 token_count、缺身份的计数器 |
| Kimi / Kimi Work | 有唯一 step ID、结束原因和最终 usage 的 step.end | 旧状态记录、缺结束证据的用量 |
| Qwen | 月度原生调用记录；会话渠道选择持久保留 | 聊天片段和无法证明互斥的渠道 |
| ZCode | 有可证明逻辑请求身份、完成状态的 model_usage | 未完成、缺身份或旧字段 |
| Pi / OMP | 经适配器核对的原生 ID 和终态记录 | 旧版本、累计及分叉归属不明 |
| OpenCode / Kilo | 仅通过版本、结束及分叉归属校验的记录 | 旧复制会话会重建 ID 的格式、口径不明的 reasoning |
| OpenClaw | 通过原生身份、结束及冷热完整性校验的记录 | 旧弱身份或继承归属不明 |
| Copilot | 具备原生 UUID 请求身份的明细 | shutdown 累计、OTel、库内行号 |
| CC Switch | 默认不直接计入 | 请求和日汇总；账号、时区、原生覆盖未证明 |
| DSH | 默认保留 live 查询 | 普通与压缩历史的原生用量；重试和结算替换生命周期尚待核对 |
| Goose / MiniMax / Hermes | 默认不直接计入 | 库内编号、会话累计、缺逐请求身份 |
| WorkBuddy / CodeBuddy / CodeBuddy IDE / Cline / Roo Code / Grok / Codebuff / Droid / Qoder / Amp / Gemini | 默认保留 live 查询 | 原生数字用量字段与必要身份元数据；不把快照伪装成独立请求 |

Kiro 现有本地格式没有可用 token 记录，保持暂停支持。具体记录不满足准入条件时，以该记录的待核对状态为准，不能从来源名称推断所有格式都已受完整保护。

## 历史不会怎样变化

同一已确认请求重复出现不再计数；后来改 token、模型或日期时保留旧贡献及冲突证据。新独立请求可以补入原发生日期。累计快照和请求明细不能相加；未知账号、时区、重置和重叠不能用猜测补齐。

Qwen 已选渠道和已采用日汇总的覆盖关系保存在账本中。源文件删除不会解除这些关系，使另一渠道重新计数。显式 forget、恢复备份和将来的人工纠错属于独立维护操作。

## 运行与恢复

候选、白名单投影和安全检查点在同一事务保存。分批发布只依赖已提交证据，服务崩溃后无需重新找到已保存的源行。单个坏文件或数据库不会清空其它来源；超限、未完成尾部及未保存就消失的目标保留缺口。

CC SQLite 来源在短只读事务中捕获固定白名单行值及指纹，完整校验后才封口；只保存键名的清单不算数值已保全。封口前失败会作废该代，封口后从本地快照继续，完成块清除重复载荷。不变快照复用，旧代只保留有效采用依赖，导入期间不长期占用上游数据库连接。文档和压缩格式有明确读取上限；超限对象会显示缺口，不声称导入完成。

维护前停止连接账本的进程，再运行 `ledger backup`、`ledger check` 或带预览的 `ledger restore` / `ledger forget`。旧库自动事务迁移；损坏或不兼容版本会拒绝写入。清除扫描缓存不清除长期账本。

账本不保存聊天正文、工具输出、提示词或密钥配置。启用前已被清理、以及两次采集之间产生又消失的记录，无法凭空恢复。

## 从旧查询切换

先保存证据，再按来源、日期、模型、粒度及各用量字段对账。缺口、未发布、未确认记录或分桶差异阻止自动切换；处理完首导不等于可以将旧看板的非零用量变成零。

旧格式缺请求身份时，可以在停服后明确选择 `ledger adopt-legacy --source codex --dry-run`。预览保存固定白名单桶、原请求时间明细和令牌，确认后用同一命令加 `--apply --preview-token <令牌>`。它冻结旧读取器的报告口径，不把它升级为核实请求；切换后完整的新扫描按先前明确选择的口径追加封闭时间区间，旧区间不再改数。范围内新增证据、删除控制及已采用贡献变化会使预览过期。超过安全预算、缺时间/模型、会话累计、来源缺口或口径无法保全时拒绝迁移并保留原查询。

首次采用与后续追加会同时封存原请求时间及用量明细。汇总事实仍是唯一总量依据，时间明细用于分时展示，不会再加一次。来源记录身份尚未核实与发生时间已知是两回事，因此分时图仍保留来源报告质量。删除上游记录、清理扫描缓存或重启服务不会清除这份时间证据。已封闭区间之后才发现、但发生时间更早的证据仍保存在库中；当前范围采用不会自动将它追加为消费，不能将“采集已保存”当作“已计入总量”。

旧版本曾把带时间的请求合并成日汇总而未封存其时间成员。升级后，后台分批核对这类旧汇总与库内保留的完整请求明细，符合原来源、模型、半开范围及逐字段金额守恒条件时，补充独立的分时修订。修订明确标记为“依据保留来源明细重建”，不会冒充采用时封存的原始成员，也不会改动原入账的 Token、费用、请求身份或质量。若已有记录显示身份、时间或内容冲突，则保留待核对，不按金额差值挑选请求或均摊小时。

历史分时恢复使用主账本内的捕获及来源投影，不依赖开发者本机备份目录。升级事务先保留待修来源预算内的完整捕获，再启动新采集，因此源文件随后清理、新捕获替换或修复分成多批都不会覆盖这份升级证据。每批进度与证据依赖均持久保存，重启可以继续；未变化且已核对失败的桶不会每次刷新重试，新证据或控制规则变化后才重新核对。恢复只在后台或维护命令中执行，不在看板查询中扫描外部文件。新安装、新工具首次采用与后续能力升级仍走原时间成员同步封存路径。

需要手动核对时，停服后执行 `ledger repair-times --limit 32 --dry-run`，确认同批预览后添加 `--apply --preview-token <令牌>`。单次有界，结果中的 `has_more` 表示还有候选；普通运行由后台继续。`status` 的 `time_repair` 字段提供修复状态。分时恢复失败不撤回原金额，也不会阻断已有看板或新数据采集。

## CC 历史补录

默认保存 CC 证据，不将全量代理明细和原生明细叠加。第一期支持两个明确入口：

- `ledger history --tool opencode` 分页查看保存的候选；相同强请求身份先查正式账本，已存在的保留旧值。可采用有明确 OpenCode 原生 session/message 身份的 schema 18 历史记录，质量为来源报告。
- Pi schema 18 的完整已封口日清单可按连续完整日期选择；必须声明历史时区，包含全部该工具模型/渠道。日调用数保持汇总粒度，不伪造逐请求记录。当前范围已有正式贡献时拒绝直接叠加。

`ledger adopt-history --request-file <JSON> --dry-run` 预览，确认后添加 `--apply --preview-token <令牌>`。请求文件的两种格式如下：

```json
{"kind":"requests","observation_ids":[123,124]}
```

```json
{"kind":"days","root_id":"<history 候选中的 root_id>","from":"2025-09-08","to_exclusive":"2025-09-10","timezone":"Asia/Shanghai"}
```

一次最多 512 个已保存观察；日范围必须完整。原生消费来源尚在 live 查询、原生证据未发布完、身份或桶语义不明、快照不完整时拒绝采用。未知历史时区不能从当前系统时区猜出。已采用范围后到的另一渠道证据不会再加一次；请求和日汇总不能用差额估算并集。

## 查询与维护边界

`quality` 单列来源报告贡献与汇总调用数。未知模型的排除筛选、无法完整纳入查询窗口的区间，进入 `membership_unknown`，不当作确定匹配。持久区间换显示时区仍保留全量总计；跨显示日期不能拆分时，图表的 `grouping_unallocated` 保留该值。单日图依次使用采用时封存的请求时间、已封存且通过校验的历史分时修订、可证明完整落在一个真实小时内的旧采用区间。仍缺少可靠成员证据、或来源确实只有日汇总时，保留“未分时”，不按比例分摊，也不只凭当前总量相等推断原分布。标准图和 3D 图共用这份读库结果。

保存、发布、源读取及续写各有独立状态。保存失败、入账失败和待恢复会显示短状态，详情在悬停提示；重启或无工作轮询不能冒充成功。

schema v7 同时保存不可变原时间明细及独立历史分时修订，旧库在写入打开时事务升级，普通页面查询不会执行迁移。不兼容身份/解析版本拒绝打开。升级前保留一致备份；回退旧二进制须同时恢复升级前备份，不能直接打开新库。`forget` 同时撤回采用贡献、时间明细、分时修订及关联证据，并保留最小防重导规则；范围控制不因最后一条证据被删除而消失。恢复旧备份需合并当前删除控制，且必须有当前采用方案及分时依赖的完整证据，否则拒绝安装。聚合区间无法可靠拆分时，半天或单请求删除会要求完整范围。
