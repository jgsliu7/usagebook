# 数据源档案 · 总览

> 版本:v1.4(v1.2 后:codebuddy/cli + codebuddy-ide 双源当日立源并实装对账 A+,档案 30;腾讯系三源齐备 workbuddy/codebuddy/codebuddy-ide;2026-10-18)
> 目的:每个 AI 编程工具的**数据采集与文件存储模式**各立一份档案,经三方取证交叉验证后,作为适配器(目录识别+文件解析)开发的**唯一输入规范**。
> 铁律:**先档案、后代码**。适配器只实现档案中已验证的行为;遇到档案未覆盖的格式,按"原样保留 + 计数上报"处理,禁止猜测性解析。
> 取证四来源:① **本机实证**(macOS 字段级样本);② **开源实现**(本地克隆的上游仓库/ 第三方统计工具源码,带 文件:行号);③ **网络资料**(官方文档 / issue / 逆向分析,带链接);④ **上游源码一手取证**(新增:直接拉取 agent 本体开源仓库分析其落盘代码——比 ② 的二手解析器证据更强, Community 源优先走此路;闭源产品降级用二进制逆向/官方 schema)。
> 证据等级:✅ 实证(有本机样本或代码行号)/ 📄 佐证(网络资料)/ ⏳ 取证中 / ❓ 未知(必须显式标注,不得编造)。

## 一、统一用量模型(所有数据源映射到此)

| 统一字段 | 含义 | 说明 |
|---|---|---|
| `input_uncached` | 未命中缓存的新输入 | |
| `cache_read` | 缓存读输入 | 单价 ≈ 输入的 10%,必须单列 |
| `cache_write` | 缓存写输入 | 单价 ≈ 输入的 125%,必须单列 |
| `output` | 模型输出(不含单列的思考) | |
| `reasoning_output` | 推理/思考输出 | 仅在源单独提供时分列(Codex/ZCode/WorkBuddy) |

- **口径标注**(每条用量必带其一):`session_total`(会话累计快照)/ `request_delta`(单请求增量)。两者不可直接混加。
- **input 语义跨源分歧(硬约束)**:Codex/ZCode/WorkBuddy.message.usage 的 `input*` **含** cache(须减除);CodeBuddy 同族同义(档案 30 §3);Claude/Kimi 的 input 字段**不含** cache;Gemini input 含 cached(ccusage)。**字段名不能判断语义,各档案 §4 映射表是唯一依据**;防御性用 tokscale"形状判定"(total==input+output 反推)。
- **维度**:工具 / 模型 / 时间(本地时区日)/ 项目(cwd)/ 会话 / 子代理。
- **成本**:只采用源自带的官方成本字段(Claude cost-state、OMP/Copilot 逐请求成本等);无官方成本一律**不估算、留空**(宁缺毋滥,对外口径)。

## 四、统一档案模板(每份档案九节)

1. 工具概况与本机安装情况
2. 目录与文件存储模式(发现规则 / 路径编码 / 环境变量 / 新旧根 / 版本演化)
3. 文件格式详解(行类型表 + 字段详解 + 本机样本路径)
4. Token/成本字段映射表(→ 统一用量模型)
5. 口径与去重陷阱
6. 开源实现参考(项目 + 文件:行号 + 做法)
7. 网络资料佐证(链接 + 可信度)
8. 兼容性风险与探测策略(多路径探测 / 格式签名 / 降级策略)
9. v1 支持结论

## 五、横切实现规范(源自七项目取证,跨源通用)

1. **幂等入队**:统计事件带内容 totalsKey(多字段 join),键相同不入队(TokenTracker `rollout.js:4042-4056`)。
2. **latest-wins 愈合**:同维度桶重复时后到且更完整者替换;append-only 文件增量消费,offset 前 1 字节必须 0x0A,未完结尾行不消费(TokenTracker `local-api.js:244-373`)。
3. **hooks 触发**(juejin):Claude `Stop/SessionEnd`、Codex `Stop` 写信号文件 + 20s 节流;信号只触发扫描,不承载数据。
4. **时间戳归一**:epoch `<1e12 则 ×1000`(秒→毫秒);聚合按本地时区转日。
5. **全零 usage 跳过;`<synthetic>` 模型跳过;未知行类型跳过+计数**——三跳过纪律。
6. **形状判定**(inclusive/exclusive):`total == input+output` 反推 input 含 cache(tokscale 三源同族 + ccr 网关三源判定 `normalization.ts:50-117`)。

## 六、演化规则

- 上游格式变更 → 补证据 → 更新档案(标注日期与样本版本)→ 增加格式签名 → 适配器跟进。
- **档案与代码不一致时,以新证据为准修代码**,禁止"代码先行、档案追认"。
- 每份档案头部维护"取证快照":取证日期、工具版本(若可得)、本机样本数。
