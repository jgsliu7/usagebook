## 1. 工具概况与本机安装情况

- Pi:终端 AI 编程 agent(harness 形态,支持 Router/Workers/Verifier 编排、原生 MCP、Codemode 沙箱);**router 型**:同一会话可把不同 turn 发给不同 provider。
- 本机实证:`~/.pi/agent/sessions/` 下 2 个编码项目目录、5 个会话 jsonl、共 155 条 assistant usage 行(**含 1 条五分量全零行,totalTokens=0;按 §5.3 三跳过纪律跳过,非零 154 条**);模型 MiniMax-M2.7(10 行)/ MiniMax-M3(145 行),provider `minimax-cn`。
- `~/.pi/agent/auth.json` 只看 keys:`["minimax-cn"]`(值未读,敏感);`settings.json` keys:`defaultModel/lastChangelogVersion/theme`。

## 2. 目录与文件存储模式(本机实证)

```
~/.pi/agent/
├── sessions/<编码cwd>/<ISO时间戳>_<uuid>.jsonl   ← 会话转录(一文件=一会话)
├── models-store.json    ← 【成本金矿】每 provider 定价表(见 §4)
├── settings.json / auth.json
```

| 项 | 结论 | 证据 |
|---|---|---|

## 3. 文件格式详解(JSONL,本机实证 version 3)

行类型(本机全集):`session`(首行:`{type:"session", cwd, id, timestamp, version:3}`)、`message`(`{type:"message", id, parentId, timestamp, message}`,role ∈ user/assistant/toolResult,**仅 assistant 有 usage**)、`model_change`(`{provider, modelId}`)、`thinking_level_change`。

**assistant message 结构投影**(本机,jq 投影非正文):

```
message: { role:"assistant", model:"MiniMax-M3", provider:"minimax-cn",
           timestamp:<epoch 毫秒数值>, responseId, stopReason, rawStopReason,
           api, content,
           usage: { input:6082, output:23, cacheRead:128, cacheWrite:0,
                    totalTokens:6233,
                    cost:{ input, output, cacheRead, cacheWrite, total },
                    cacheWrite1h:0,
                    reasoning:133 } }        ← reasoning 可为 null(按 0)
```

## 4. Token/成本字段映射表

| 源字段(usage.*) | 统一模型 | 口径 |
|---|---|---|
| `input` | `input_uncached` | request_delta(**exclusive,直取不减除**) |
| `cacheRead` | `cache_read` | request_delta |
| `cacheWrite` | `cache_write` | request_delta(`cacheWrite1h` 另列,本机恒 0;若非 0 不可与 cacheWrite 混加,❓ 单独上报) |
| `output` | `output`(含推理) | request_delta |
| `reasoning`(null→0) | `reasoning_output`(output 子集) | request_delta |
| `totalTokens` | 校验恒等式(= 前四桶和) | — |
| `cost.total` | `cost_usd`(**客户端估算口径**,标注非官方账单) | request_delta |

- **input 语义(exclusive)本机硬互证**:首条样本 4803+15289+0+540 = 20632 = totalTokens,精确闭合;155 行无一例外。
- **成本是客户端逐请求计算**:`cost` 分量之和 = `cost.total` 精确成立(0.0014409+0.000648+0.00091734+0 = 0.00300624);单价反推自 `models-store.json`:4803 tok→$0.0014409 = **$0.3/Mtok** = 表中 MiniMax-M2.7 `cost.input:0.3`(output 1.2 / cacheRead 0.06 / cacheWrite 0.375,全部对上)。
- **models-store.json**(本机实证结构):`{ "<provider>": { models: [ { id:"MiniMax-M2.7", api:"anthropic-messages", provider, cost:{input,output,cacheRead,cacheWrite}($/Mtok), contextWindow:204800, … } ], checkedAt:<epoch ms> } }`——多 provider 定价表,可作自算成本与模型元数据来源。
- 时间戳(**实现勘误**):本机 155/155 实证 `message.timestamp` 为 **epoch 毫秒数值**(行级 `entry.timestamp` 才是 ISO 字符串)——解析两种都认,数值按 `<1e12 ×1000` 归一;juejin `coerceTimestampMs` 同款规则。

## 5. 口径与去重陷阱

1. **去重键:行级 `entry.id`**(顶层 id,非 message 内字段)。juejin:seenIds 集合封顶 50k 条滚动(`pi.ts:240`);TokenTracker:seenIds + 文件游标 `{size, mtimeMs, ino}`。统一键格式建议 `pi:{session文件名}:{entry_id}`。
2. **增量消费游标**:inode 变化或文件变小 → 从 0 重读(juejin `pi.ts:159-166`;TokenTracker `rollout.js:16104-16107`);**半行防御**(TokenTracker 独有,`rollout.js:16115-16127`):只提交到最后一个物理换行符 `Math.min(lastCompleteOffset, postStat.size)`,写半行的 JSON 不会因解析失败被永久跳过。
3. **全零跳过**:五分量全 0(或 usage 缺失)→ 标记 seen 并跳过(juejin `pi.ts:198-201`;TokenTracker `rollout.js:16151-16162`)。
4. **reasoning 字段名分裂(关键版本陷阱)**:本机 version 3 写 **`reasoning`**;juejin `normalizePiUsage` 与 TokenTracker `parsePiLikeIncremental`(`rollout.js:16149`)读 **`reasoningTokens`**——两者对本机新文件都会取 0(不炸但漏推理桶)。TokenTracker 的 omo 配置用别名族 `["reasoningTokens","reasoning"]`(`rollout.js:15827`)是正确防御。**适配器必须取 `reasoning ?? reasoningTokens ?? 0`**。
5. **与 omp 双计防御**:`PI_CODING_AGENT_DIR` 为 pi/omp 共享环境变量;TokenTracker 用 `decidePiCodingAgentDirOwner` 把覆盖路由给唯一下属源,并显式 `piAgentDirCollidesWithOmp` 碰撞检查(`rollout.js:15873-15890`),保证同一 sessions 目录绝不被两个源各扫一遍。**本项目 pi 与 omp 适配器(另案档案)必须共享此纪律**。
6. **router 型 source 拆分**:同一会话不同 turn 可能走不同 provider;TokenTracker 按 `msg.provider` 把 source 拆成 `pi-<provider-slug>`(`rollout.js:15975-15990`),防不同后端的 turn 塌缩进同桶或继承错定价。本项目 v1 可先统一 `pi` 源 + model 字段自带型号,provider 记入扩展字段。
7. model 缺失兜底:`pi-unknown`(两家一致);本机 assistant 行 model 均在场。
8. 同族邻居:Prime Agent(`~/.prime/agent/sessions/<session-id>.jsonl` 平铺布局)持久化**同一 usage 信封**(TokenTracker `rollout.js:15909-15928`)——将来支持时复用 pi 解析器,仅换根路径与去重键前缀。

## 8. 兼容性风险与探测策略

| 风险 | 对策 |
|---|---|
| reasoning 字段名版本分裂(reasoning / reasoningTokens) | 别名族 `reasoning ?? reasoningTokens ?? 0`;null 按 0 |
| version 字段演化(本机 3) | 行 keys 指纹 + totalTokens 恒等式校验,失配行计数上报不静默 |
| pi/omp 共享 PI_CODING_AGENT_DIR 双计 | 与 omp 适配器共享"唯一属主"判定;默认根不同(`~/.pi` vs omp 根)时各自扫,显式覆盖碰撞时禁其一 |
| router 多 provider 定价混淆 | cost 直取 `usage.cost.total`(客户端已按 provider 表算好);自算成本时用 models-store.json 对应 provider 条目 |
| cacheWrite1h 语义(本机恒 0) | 单列观察,不并入 cache_write;非 0 时上报待考证 |
| 写半行/文件轮转 | inode+size 游标,缩小即重读;换行边界提交 |
| auth.json 凭据 | 只读 keys 不读值;会话正文不入档案 |

## 9. v1 支持结论

**✅ 支持(v1 新增源)。** 三方链完整:本机字段级(155 条 usage 全量 jq 复算、exclusive 互证、定价反推)、开源双解析器(juejin + TokenTracker 逐行读毕,含增量/去重/双计防御全套)、网络方向佐证。**五桶映射一句话:`input/cacheRead/cacheWrite/output/reasoning` 五字段直取(input 本就是 exclusive,零减除),`cost.total` 作客户端估算成本,`totalTokens` 作恒等式校验。** 档案冻结 v1.0,可写适配器(JSONL 全量扫,无需 SQLite)。
