# 数据源档案:候选源快评(第 05 轮)

> 目的:对 v1 五源(claude/codex/kimi/zcode/workbuddy)之外的候选数据源做快速识别与定级。
> **硬标准:本机有没有 token 用量数据。** 结构/字段细节留给单独立档案的专项取证。
> 方法:本机勘察 ✅ + 本地克隆的上游仓库 13 项目 grep + 档案 03/06 既有结论。
> 关键发现:**juejin-usage 项目自带 30+ 解析器,与本机候选清单高度重合(dsh/minimax-code/omp/pi/qoder/hermes/mimo/cline/codebuddy/opencode 均有 parser)**,是下一批档案的第一参考蓝本。

---

## 1. cc-switch(`~/.cc-switch/cc-switch.db`)—— ⭐ 意外金矿,高优先

> ⚠️ **机制修正(以 [13-cc-switch](13-cc-switch.md) 为准)**:本段初判"网关侧账本、不读转录"**错误**——本机 `proxy_request_logs` 零条 `data_source='proxy'`,四个通道(session_log/codex_session/opencode_session/pi_session)全部是 CLI 转录文件的**同步镜像**(session_log_sync 游标 5,904 文件 = 适配器同一批输入,路径级证实)。

- **是什么**:Claude/Codex 供应商切换器 + 本地代理(AIUsage-sylearn 的 PROXY_ARCHITECTURE 文档证实其代理角色);v3.13+ 用量统计**双数据源**:代理日志通道(需代理+接管+日志三前置,本机未启用)+ CLI 会话日志镜像通道(本机全部数据来自此通道)。
- **本机数据画像**(sqlite 只读实证):
  - `proxy_request_logs` **81,321 行**:请求级五桶 + 分桶成本(input/output/cache_read/cache_creation cost usd)+ session_id + created_at(epoch 秒);app_type 分布 claude 44,392 / codex 29,169 / **opencode 7,627 / pi 155**;行级表仅保留 ~30 天(滚动清理 实测 MIN created_at≈2026-09-06)。
  - `usage_daily_rollups` **261 行日汇总**:覆盖 **2026-03-28 → 2026-09-06**(恰好是 Claude 转录被 30 天 GC 清掉的整个历史空窗!),22 个模型(glm-5.1/5.2/5.3、k3、gpt-5.4/5.5/5.6-sol、deepseek-v4-pro…),含 total_cost_usd 与 `input_token_semantics` 语义标注列。
  - `session_usage_dedup`(155 行)已带去重键设计(data_source/request_id/semantic_id)。
- **判定**:✅ 有用量(且带官方口径成本)。**但与 ~/.claude、~/.codex 转录高度重叠——必须设计跨源去重/补洞口径**(rollups 补 GC 空窗,近期请求与转录二选一),否则双计。
- **优先级**:**高**(它是产品愿景里"内部愿景条目/30 天清理补救"的现成答案,还白送成本数据)。

## 2. Cline(`~/.cline/`,1.5G)—— ✅ 有用量,高优先

- **是什么**:开源 VSCode AI 编程插件/Cline 应用;juejin-usage 有 `parsers/cline.ts`。
- **本机数据画像**:`data/sessions/<epoch_ms>_<id>/<id>.messages.json`(**840M 会话数据**,非 jsonl)+ `data/db/`(679M:tasks.db/sessions.db 等 8+ 库)。messages.json 实证含 `inputTokens` 字段;tasks.db/sessions.db 无 token 列(用量在会话文件里)。
- **判定**:✅ 有用量,数据量大,parser 蓝本现成。
- **优先级**:**高**。

## 3. OMP(`~/.omp/`,101M)—— ✅ 有用量,高优先

- **是什么**:OMP agent(用户点名);juejin-usage 有 `parsers/omp.ts`。
- **本机数据画像**:`~/.omp/agent/` 下 `agent.db`(表:**model_usage / usage_history / usage_cost_history / client_usage** —— 一整套用量账本)+ `history.db` + `models.db` + sessions/。
- **判定**:✅ 有专用用量库,结构清晰。
- **优先级**:**高**。

## 4. Pi(`~/.pi/`)—— ✅ 有用量(含成本),高优先

- **是什么**:pi agent(用户点名);juejin-usage 有 `parsers/pi.ts`;cc-switch 里也有 pi_session 通道 155 条请求(~~互证走代理~~ **修正:转录镜像通道**,见 13-cc-switch §5.1)。
- **本机数据画像**:`agent/sessions/<编码路径>/<RFC3339>_<uuid>.jsonl`,assistant 行实证携带 `"usage":{"input","output","cacheRead","cacheWrite","totalTokens","cost":{**分桶 USD 成本**}}` —— **自带成本字段的转录源,与 Claude cost-state 同级的金矿**。
- **判定**:✅ 有用量 + 官方口径成本。
- **优先级**:**高**(数据量小但取证价值高)。

## 5. DeepSeek DSH(`~/.dsh/`,33M)—— ⏳ 待深挖(用户点名)

- **是什么**:DeepSeek DSH;juejin-usage 有 `parsers/dsh.ts`。
- **本机数据画像**:`sessions/<编码路径>/`(与 Claude projects 同款编码)+ `storages/` + profiles。
- **判定**:⏳ 会话目录结构在,用量字段待专项取证(本目录已列独立档案计划)。
- **优先级**:**中高**。

## 6. MiniMax(`~/.minimax/`,205M + App Support/MiniMax)—— ⏳ 待深挖(用户点名)

- **是什么**:MiniMax agent;App Support/MiniMax 桌面应用也在。
- **本机数据画像**:`sqlite.db`(仅 20KB,初判非用量账本)+ `agents/{coder,general,mavis,verifier}/`(子代理目录体系,结构与 Kimi agents/ 相似);juejin-usage 有 `parsers/minimax-code.ts`。
- **判定**:⏳ agents/ 子树 + App Support 待专项取证。
- **优先级**:**中高**。

## 7. Hermes(`~/.hermes/`,2.4G)—— ✅ schema 金矿,低数据量

- **是什么**:开源个人 AI agent 框架 hermes-agent(本机 AGENTS.md 自述:同一 agent core 跑 CLI/Telegram/Discord 等 20+ 平台);默认模型 deepseek-reasoner(DeepSeek 生态强关联)。
- **本机数据画像**:`state.db` 的 `sessions` 表列集堪称完美:**input/output/cache_read/cache_write/reasoning_tokens + estimated_cost_usd + actual_cost_usd + cost_status + pricing_version + api_call_count**。但本机仅 1 会话/10 消息(2.1G 是 agent 运行时本体,非数据)。
- **判定**:✅ schema 完整但本机几乎没用过;juejin-usage 有 `parsers/hermes.ts`。
- **优先级**:**中**(装了没用,统计价值趋零,但 schema 值得记档)。

## 8. Qoder(`~/.qoderworkcn/` + App Support/QoderWork CN)—— ❌ 本机无 token 用量落地

- **是什么**:阿里 Lingma 系 agent Qoder(会话内记忆实证官方文档在 help.aliyun.com/zh/lingma/qodercli-cn);juejin-usage 有 `parsers/qoder.ts`。
- **本机数据画像**:`projects/<编码路径>/<uuid>.jsonl` 为 **Claude-Code 形状的转录**(type=assistant/message/user/tool_use/thinking,含 isSidechain/version),共 4 文件/1.5M(2026-07);**assistant 行无 message.usage**(grep 到的 "usage" 全是记忆工具的字节配额,如 422/4096 bytes);App Support `agents.db` 是 IM 型聊天库(chats/messages/ms365_auth/voice_input),无 token 列。
- **判定**:❌ 本机未观测到 token 落地(用户仅试用)。**注意:转录形状是 Claude-Code 系,若 Qoder 后续版本写入 usage,按档案 01 的解析骨架即可低成本接入**。
- **优先级**:**低**(留运行时探测钩子)。

## 9. CodeBuddy(`~/.codebuddy/` + App Support/CodeBuddyExtension)—— ❌ 本机无数据

- **是什么**:腾讯 CodeBuddy(与 WorkBuddy 同族,tokscale 共用 tencent_buddy 解析器;juejin-usage 有 `parsers/codebuddy.ts`)。
- **本机数据画像**:~/.codebuddy 仅 memwatch 日志;App Support/CodeBuddyExtension/Data **只有 auth 信息文件**(workbuddy-desktop.info —— 与 ~/.workbuddy 同一账号体系)。真正的会话数据在本机即 ~/.workbuddy/projects(档案 05 已覆盖)。
- **判定**:❌ 无独立用量数据(与 WorkBuddy 同根同源)。
- **优先级**:**低**(档案 05 已覆盖其数据面)。

## 10. kimi-work(`~/.kimi-work/`)—— ❌ 本身无数据(桌面端另有根)

- tokscale README 实证:kimi-work = Kimi 桌面端,**数据根在 `~/Library/Application Support/kimi-desktop` 的 app-data(自动发现)**,即档案 03 §2 已记的"桌面嵌入式 daimon-share"路径族。~/.kimi-work 本机仅 bin/(kimi-slides/kimi-tools 辅助工具)。
- **判定**:❌ 无独立数据;归档案 03 的桌面根体系。
- **优先级**:**低**(随档案 03 v1.1 桌面根一起处理)。

## 11. TRAE CN(`~/.trae-cn/`,72M)—— ❌ 与主档案 06 同布局无新数据

- 布局与 ~/.trae 同族(VSCode fork:builtin/extensions/mcps/skill-config);72M 里 71M 是 builtin 运行时;无独立用量发现。**与档案 06 的结论合并:v1.1 随 TRAE 三路线评估走**(vscdb icube / SOLO database.db / 账号 API)。
- **判定**:❌ 快评级无新证据,不单独立档案。

## 12. dws(`~/.dws/`)—— ❌ 无用量数据

- DingTalk 侧服务(clientId `ding…`, DingTalk webhook/机器人生态旁证);logs/dws.log 无 token/usage 字样(grep=0);cache/skills 非会话。
- **判定**:❌ 非编程 agent 用量源。

## 13. hopet(`~/.hopet/`)—— ❌ 无用量数据

- Claude Code 伴侣工具(config.listeners.claudeCode=true;hopi 主题系统);state/ 与 run/ 为空。
- **判定**:❌ 非用量源。

## 14. mimocode(`~/.mimocode/`)—— ❌ bin-only(但 juejin 有 parser 备用)

- 仅 `bin/mimo`;juejin-usage 有 `parsers/mimo.ts`(OpenCode 系存储,SQLite 读法 + provider allowlist 只收 mimo/xiaomi 原生行、丢弃 anthropic 镜像)。若用户启用 mimo,其数据大概率落在 OpenCode 布局(见 §15 opencode)。
- **判定**:❌ 本机未启用;parser 蓝本已定位。

## 15. opencode(本机在用,本地根已实证)—— ✅ 有用量,待立档案

> ✅ **悬案解决(13-cc-switch §5.4)**:上述"两种可能"中 ② 成立——cc-switch session_log_sync 的 opencode 条目为虚拟路径 `~/.local/share/opencode/opencode.db:ses_*`,**本机 opencode 本地根 = `~/.local/share/opencode/opencode.db`(SQLite,自身会话/用量库)**;cc-switch 的 7,649 条 opencode 行与 rollups 均为其镜像。juejin-usage 有 `parsers/opencode.ts`(deriveOpencodeMessageKey/normalizeOpencodeTokens 被 mimo.ts 复用)。
- **判定**:✅ 有用量(本地 opencode.db 直读,待立档案;cc-switch rollups 仅兜底)。
